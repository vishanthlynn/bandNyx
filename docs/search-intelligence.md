# NYX Search Intelligence setup

The engine is repository-native and runs without credentials for audits,
registry validation, artifact synchronization and page proposals.

## Local commands

```bash
python3 -m scripts.search_intel validate-data
python3 -m scripts.search_intel sync
python3 -m scripts.search_intel audit
python3 -m unittest discover -s tests -v
```

`sync --write` updates `sitemap.xml`, `seo-query-map.json` and `llms.txt` from
the current canonical pages and repository registries.

`propose-pages` reads `seo/gigs.json` and writes only to `seo/proposals/`.
Nothing generated by that command is published automatically.

## Google Search Console API

The verified property is:

```text
https://band-nyx.vercel.app/
```

It must include the trailing slash and is a URL-prefix property.

1. Create a Google Cloud project.
2. Enable the Google Search Console API.
3. Create a service account and download its JSON key.
4. In Search Console, add the service-account email as a Full user for the
   property above.
5. In the GitHub repository, add an Actions secret named
   `GSC_SERVICE_ACCOUNT_JSON` containing the complete JSON key.
6. Add `SEO_PR_TOKEN`, a fine-grained GitHub token allowed to write repository
   contents and open pull requests.
7. Run the **Weekly search intelligence** workflow manually once.

Raw page/query rows and the URL Inspection cache are uploaded as a private
Actions artifact with 30-day retention. The public branch receives only
aggregate totals, page-level opportunities, sitemap status and inspection
verdict counts.

Performance collection ends three days before the run and requests finalized
data. Page totals are used for headline metrics because Search Console may
omit anonymized queries.

URL Inspection reads Google's indexed version; it does not request indexing.
The engine skips inspections cached within seven days and caps each run at 100
URLs.

## Competitor intelligence

There is no official Google API that returns ordinary Google competitor
rankings. Do not use the Indexing API for this site and do not scrape search
results.

Use `seo/imports/serp/template.csv` for:

- manual observations;
- licensed provider exports;
- organizer or directory result research gathered under the source's terms.

Run `validate-data` before accepting an import. The generated report summarizes
competitor domains and appearances without publishing unsupported ranking
claims on the website.

## Verified performance pages

A gig can produce a proposal only when it has:

- `status: verified`;
- an exact `YYYY-MM-DD` date;
- a named venue and city;
- a unique recap;
- at least one independent HTTPS evidence URL.

Aggregate claims such as “50+ shows” cannot create individual event pages.
Unknown year-range dates are not valid Event structured data.

## WhatsApp attribution

The public CTA uses `+91 79950 22614`. Each placement has a unique reference
code in `seo/wa-codes.json`, included in the prefilled message.

`analytics.js` emits a `whatsapp_click` event through `gtag` when GA4 is
configured. Until a GA4 measurement ID or approved Vercel event store is
added, the reference remains visible in the incoming WhatsApp message but no
automatic count is claimed.

## Publishing policy

Vercel is the only indexable host. The former GitHub Pages deployment was
removed because it did not apply Vercel redirects and could expose retired
doorway URLs.

The quality gate rejects:

- redirect sources in sitemaps or internal links;
- canonical mismatches, noindex sitemap entries and orphan pages;
- invalid JSON-LD or unverified Event dates;
- unsupported “best” claims;
- highly similar indexable pages;
- query maps or WhatsApp codes assigned to non-canonical pages.
